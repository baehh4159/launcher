# 책상·공책 UX 연구 — "책상 런처"를 진짜 책상처럼

> 작성 2026-11-28 · 상태: **제안(구현 전)** — 채택된 항목만 PRD §5에 기능 ID로 옮겨 구현한다.
> 전제 기기: Galaxy S24+ (6.7", 약 384×832dp, S Pen 없음 → 손가락 입력), 한 손·오른손 엄지 위주.

## 0. 한 장 요약

책상과 공책이 강한 이유는 '예뻐서'가 아니라 다음 네 가지 때문이다.

1. **꺼내 둔 것은 눈에 보이고, 보이는 것은 잊히지 않는다.** 책상 위 더미는 그 자체로 '할 일 알림'이다.
2. **놓을 곳을 정하지 않아도 일단 놓을 수 있다.** 분류(파일링)는 나중에, 포착(메모)은 지금.
3. **공간이 유한하다.** 책상이 꽉 차면 치워야 하고, 치우는 순간 정리·회고가 일어난다.
4. **공책은 한 방향으로 쌓인다.** 날짜순, 쪽수 유한, 되돌아가 고치기보다 다음 장에 이어 쓴다.

지금 앱은 '서류철을 꺼내 펼친다'(①의 일부)까지는 책상을 닮았지만, **책상 면이 비어 있는 배경**이고 **도구가 서로 분리된 앱**처럼 동작한다.
가장 효과가 크고 지금 구조로 바로 만들 수 있는 세 가지를 먼저 제안한다.

| 순위 | 제안 | 한 줄 설명 |
|---|---|---|
| ★1 | **책상 위에 꺼내 두기** | 할일·메모·문서·포스트잇을 책상 면에 카드로 올려 둔다. 홈 화면 = 지금 내가 붙잡고 있는 것들 |
| ★2 | **포스트잇 즉석 메모** | 책상 빈 곳을 두 번 탭 → 그 자리에 포스트잇. 분류 없이 3초 포착 |
| ★3 | **책상 치우기 (하루 마감)** | 저녁에 책상 위 카드를 하나씩: 내일로 넘기기 / 공책에 보관 / 버리기. 다 치우면 빈 책상 + "오늘 끝" 도장 |

그다음 단계로 **"오늘 페이지" 공책**(불렛저널식으로 할일·일정·메모를 한 장에)과 **공책꽂이·책장**을 제안한다 (§8 로드맵).

## 1. 왜 책상과 공책은 생산성이 높은가 — 원리와 근거

| # | 원리 | 근거 | 앱에 주는 함의 |
|---|---|---|---|
| P1 | **보이는 것이 기억을 대신한다 (상기 기능)** | Malone(1983): 사람들은 책상 위 '더미(pile)'를 분류하기 어려워서만이 아니라 **눈에 띄어 할 일을 떠올리게 하려고** 둔다. Kidd(1994): 지식노동자는 책상 위 자료의 **공간 배치 자체**를 작업 상태 표시로 쓰고, 서류를 파일에 넣는 순간 의식에서 사라진다 | 진행 중인 것은 **서랍(앱) 속이 아니라 책상 면에 보여야** 한다. 지금 홈은 시계뿐이라 상기 기능이 없다 |
| P2 | **분류는 비싸다 — 먼저 놓고 나중에 정리** | Malone(1983) '파일 vs 더미': 파일링은 범주 결정 비용이 커서 미뤄진다. Whittaker & Hirschberg(2001): 미리 분류해 보관한 종이 대부분은 다시 열리지 않는다 | 포착 순간에 "어느 도구/프로젝트?"를 묻지 않는다. **포스트잇 → 나중에 공책으로** 2단계 |
| P3 | **공간 기억은 강력하다** | Robertson 외(1998) Data Mountain: 문서를 2.5D 공간에 직접 배치하게 하자 목록(즐겨찾기)보다 다시 찾기가 빨랐다. Agarawala & Balakrishnan(2006) BumpTop: 물리감 있는 더미·던지기로 데스크톱 정리가 자연스러워짐 | 카드는 **놓은 자리에 그대로** 있어야 한다(자동 정렬 금지). 위치가 곧 기억 단서 |
| P4 | **종이는 동시에 펼치고, 쓰면서 읽는다** | Sellen & Harper(2002) *The Myth of the Paperless Office*: 종이의 핵심 어포던스는 여러 문서를 나란히 펼치기, 읽으며 쓰기(주석), 빠른 훑어 넘기기 | 한 공책을 펼친 채 **옆에 참고 카드 하나**를 둘 수 있으면 좋다. 넘김은 빠르고 가벼워야 한다 |
| P5 | **적어 두면 머리가 비워진다** | Masicampo & Baumeister(2011): 끝내지 못한 목표는 계속 머리를 맴돌지만, **구체적 계획을 적으면** 그 간섭이 사라진다. Risko & Gilbert(2016) 인지 오프로딩 | 포착은 즉시, 마감 의식에서는 "다음에 언제 할지"까지 적게 한다 (§4.5) |
| P6 | **의식(ritual)이 일의 경계를 만든다** | Newport(2016) *Deep Work*의 '셧다운 의식'; 불렛저널(Carroll, 2018)의 **이월(migration)** — 넘길 때마다 "아직 할 가치가 있나?"를 묻는다 | **책상 치우기**를 하루 끝 의식으로. 넘길 때마다 다시 판단하게 해 할일 목록이 썩지 않게 |
| P7 | **한 번에 하나만 펼친다** | Mark 외(2008): 방해받은 작업은 더 빨리 끝내지만 스트레스·부담이 커진다. 책상에서는 앞에 펼친 공책 하나가 '지금 하는 일' | 이미 맞음: 팝업 창은 한 번에 하나. 알림·배지로 책상을 어지럽히지 않는다 |
| P8 | **손으로 쓰면 다르게 기억된다 (단, 과장 금지)** | Mueller & Oppenheimer(2014)는 손필기가 개념 이해에 유리하다고 보고했지만, Morehead 외(2019) 재현 연구에선 효과가 약했다. 종이 읽기 이해도는 화면보다 약간 낫다는 메타분석(Delgado 외, 2018) | 손글씨를 강요하지 않는다. **선택지로** 포스트잇·여백 낙서를 손가락으로 끄적일 수 있게(이미 낙서장 엔진 있음) |
| P9 | **흔적과 두께가 진척을 보여 준다** | 공책이 두꺼워지고 페이지가 닳는 것은 '내가 해 온 일'의 물리적 증거 (설계 관찰) | 공책 등 두께·쪽수, 다 쓴 공책은 **책장**으로. 스트릭 숫자 대신 '쌓인 종이'로 보여 준다 |

## 2. 지금 앱 진단

**이미 책상다운 것**
- 왼쪽 서류철을 엄지로 훑어 꺼내고 팝업 창으로 펼친다 → '꽂혀 있는 것을 꺼내 앞에 펼친다'는 동작이 살아 있다.
- 종이 톤 팔레트·얇은 선·그림자 없음, THUD 햅틱 → 종이·나무의 질감 방향이 맞다.
- 한 번에 창 하나(P7).

**책상답지 않은 것**
| 문제 | 왜 문제인가 | 관련 원리 |
|---|---|---|
| 책상 면이 비어 있고 시계만 크다 | 홈을 볼 때마다 "지금 내가 뭘 하던 중인지"가 안 보인다 | P1 |
| 메모하려면 서류철 선택 → 도구 → 새 항목 → 분류 | 포착 비용이 커서 결국 다른 앱(카톡 나에게 쓰기)으로 샌다 | P2, P5 |
| 할일·메모·일기·캘린더가 각각 다른 앱 | 공책 한 장에 섞어 쓰던 맥락이 쪼개진다 | P4, 불렛저널 |
| 하루의 끝이 없다 | 미완료가 무한히 쌓이고, 다음 날 아침이 어제와 구분되지 않는다 | P6 |
| 다 쓴 것·지난 것의 무게감이 없다 | 기록이 쌓이는 보람이 안 보인다 | P9 |

## 3. 제안하는 공간 모델

책상 한 장을 다섯 구역으로 본다. 모두 **지금 화면 안**에서 구현한다(새 화면 계층을 늘리지 않음).

```
┌──────────────────────────────────┐
│ 벽   11월 28일 토 · 오후 3:24 · 7℃   │ ← 벽: 작게. 시계·날짜·(다음 일정 한 줄)
├──────────────────────────────────┤
│▌                                │
│▌  ┌────────┐   ┌──────┐         │
│▌  │오늘 페이지│   │포스트잇│  ┌────┐ │ ← 책상 면: 꺼내 둔 카드들
│▌  │• 견적서  │   │우유,  │  │스캔 │ │   (놓은 자리에 그대로)
│▌  │○ 3시 미팅│   │계란   │  │계약서│ │
│▌  │– 아이디어 │   └──────┘  └────┘ │
│▌  └────────┘     ┌──────┐   ░░░ │
│▌ 공책꽂이            │할일:  │   ░░░ │ ← 오른쪽 32–96dp: 보이지 않는
│▌ (왼쪽 서류철)        │은행   │   ░░░ │   훑기 영역(지금 그대로)
│▌                   └──────┘   ░░░ │
│▌                               │
│   🗑 휴지통            📥 서류함   │ ← 바닥: 휴지통(왼쪽)·서류함(받은 것)
└──────────────────────────────────┘
       ︿ 위로 밀면 서랍(앱)
```

| 구역 | 실물 | 앱에서 | 지금과 차이 |
|---|---|---|---|
| **벽** | 벽시계·벽걸이 달력 | 상단 한 줄: 날짜·시각·다음 일정 | 큰 시계를 작게 줄여 책상 면을 넓힌다 |
| **책상 면** | 지금 하는 일들이 놓인 곳 | **꺼내 둔 카드**(포스트잇·할일·메모 쪽·문서·낙서). 최대 개수 제한 | 신규 (★1) |
| **공책꽂이** | 책상 위에 세워 둔 공책·서류철 | 지금의 왼쪽 서류철. 각 도구 = 공책 한 권 | 그대로, 이름만 '공책'으로 |
| **서랍** | 책상 서랍 | 앱 서랍(위로 밀기·맨 끝 서류철) | 그대로 |
| **휴지통·서류함** | 쓰레기통, 받은 서류함 | 버린 카드 7일 보관 / 공유받은 것·스캔 직후 문서가 일단 들어오는 곳 | 신규 |

**책상 면의 크기 제한**: 카드 최대 8장(S24+ 한 화면에 겹치지 않고 손가락으로 잡을 수 있는 수). 꽉 차면 새로 꺼낼 때 "책상이 꽉 찼어요 — 하나 치우기"를 띄운다. 제한이 곧 정리의 계기다(P1·P6). 숫자는 실기기에서 조정.

## 4. 핵심 상호작용

### 4.1 책상 위에 꺼내 두기 ★1
- **무엇**: 어떤 도구 안의 항목이든 길게 눌러 "책상에 꺼내 두기" → 팝업이 닫히며 그 항목이 카드로 책상 면에 툭 떨어진다.
- **카드**: 항목 종류별 얼굴 — 할일(체크박스 + 제목, 카드에서 바로 체크), 메모 쪽(첫 3줄), 문서(첫 장 썸네일), 낙서(썸네일), 일정(시각).
- **배치**: 놓은 자리에 그대로(P3). 다만 작은 화면이라 **느슨한 격자**(4열 스냅)에 ±1.5° 무작위 기울기로 종이 느낌. 길게 눌러 끌어 옮기기, 다른 카드 위에 놓으면 **더미**(겹친 모서리 보임, 탭하면 부채꼴로 펼침).
- **카드를 탭**하면 원래 공책의 그 쪽이 팝업으로 펼쳐진다(원본과 연결, 복사 아님).
- **왜**: 홈을 켤 때마다 진행 중인 일이 보인다(P1). 런처라서 가능한, 일반 메모 앱이 못 하는 지점.

### 4.2 포스트잇 즉석 메모 ★2
- 책상 빈 곳 **두 번 탭** → 그 자리에 노란 포스트잇, 바로 키보드. 쓰고 바깥 탭하면 끝. 분류 질문 없음(P2).
- 포스트잇 위에서 **손가락으로 끄적이기** 전환(낙서장 엔진 재사용, P8 — 선택 사항).
- 포스트잇을 공책꽂이(왼쪽 서류철)로 **끌어다 놓으면** 그 공책으로 들어간다: 할일 공책 → 할일, 메모 공책 → 메모 쪽. 이것이 '나중에 분류'.
- 화면 꺼진 상태 대신 홈 버튼 한 번 → 두 번 탭, 2동작이면 메모 시작.

### 4.3 오늘 페이지 (공책 한 장에 섞어 쓰기)
- 불렛저널 '빠른 기록(rapid logging)'을 그대로: `•` 할일, `○` 일정, `–` 메모, 줄 맨 앞 기호만 바꿔 종류 전환.
- 저장은 기존 표(todo·calendar_event·memo)로 나눠 들어가고, 오늘 페이지는 **그날 날짜로 모아 보는 뷰**다 → 1단계는 스키마 변경 없이 가능.
- 기본으로 책상 면 왼쪽 위에 '오늘 페이지' 카드가 펼쳐져 있다(꺼내 두기의 특별한 카드).
- 상태 기호: `×` 완료, `>` 내일로 넘김, `<` 날짜 정해 미룸, 취소선 = 안 하기로.

### 4.4 공책꽂이 — 공책 꽂기·새 공책
- 왼쪽 서류철 = 공책의 **등(spine)**. 색 = 표지 색, 두께 = 쓴 쪽수(로그 눈금, 최대 두께 제한)로 쌓인 정도가 보인다(P9).
- **새 공책**: 프로젝트 하나 = 공책 한 권(지금의 '프로젝트 메모'가 공책으로 승격). 도구함의 '켜기'는 '꽂기'로 표현.
- **다 쓴 공책**(프로젝트 끝) → "책장에 꽂기": 왼쪽에서 빠지고 책장(설정 안 보관함)으로. 데이터는 그대로.
- 공책 안에서는 **가로로 넘겨 쪽 이동**(무한 스크롤 대신 쪽 단위, 쪽마다 날짜). 넘김 THUD + (선택) 넘김 소리(SHELL-13).

### 4.5 책상 치우기 — 하루 마감 의식 ★3
- **언제**: 사용자가 정한 시각(기본 오후 9시)에 벽에 작은 "책상 치울 시간" 쪽지. 알림 팝업은 띄우지 않는다(P7). 버튼으로 언제든 시작 가능.
- **어떻게**: 책상 위 카드가 한 장씩 가운데로 오고, 엄지로 세 방향 중 하나:
  - **위로 밀기 → 내일 책상으로**(불렛저널 이월 `>`). 이때 "언제 할지" 한 줄(P5)을 선택적으로.
  - **왼쪽으로 밀기 → 공책에 보관**(원래 공책으로, 카드만 내려감).
  - **아래로 밀기 → 버리기/완료**(휴지통, 7일 보관).
  - 같은 카드를 3일 연속 넘기면 "계속 넘기고 있어요 — 정말 할 일인가요?"(불렛저널 이월의 질문).
- **끝**: 빈 책상 + "오늘 끝" 도장 + 오늘 완료 수를 **쌓인 종이 장수**로 표시(숫자 강조 X). 다음 날 아침엔 넘긴 카드만 놓인 깨끗한 책상.
- **왜**: 미완료를 머리 밖으로 내보내고(P5) 하루의 경계를 만든다(P6). 하지 않아도 벌칙 없음 — 그냥 다음 날 책상이 어지럽다(실제 책상처럼).

### 4.6 구겨 버리기·휴지통
- 카드를 **휴지통으로 끌기** 또는 두 손가락 오므리기(구기기) → 구겨지는 애니메이션 + 짧은 THUD 두 번.
- 휴지통 탭 → 최근 7일 버린 것, 꺼내면 원위치. 실수 비용을 낮춰 과감히 치우게 한다.

### 4.7 종이 감각 (전 도구 공통)
- 공책마다 **속지 선택**: 줄·모눈·무지·점선(도트). 배경 패턴은 designsystem 토큰으로 그린다(이미지 불필요).
- 팝업 창 = 펼친 공책: 가운데 제본선(아주 옅게)은 넓은 화면에서만. 폰에선 한 쪽만.
- 스큐어모피즘은 **질감이 아니라 동작**으로: 나무결·가죽 텍스처 대신 넘김·꺼내기·구기기·쌓기의 물리감과 햅틱.

## 5. 하지 말 것 (안티패턴)

| 하지 말 것 | 이유 |
|---|---|
| 무한 캔버스 책상 | 유한함이 정리를 만든다(§3). 폰에선 길도 잃는다 |
| 자동 정렬·자동 정리 | 놓은 자리가 기억 단서(P3). 정리는 사용자의 의식이어야 한다(P6) |
| 배지·빨간 숫자·잦은 알림 | 책상은 사용자를 부르지 않는다(P7). 벽 쪽지 한 장이 최대 |
| 나무·가죽 사진 텍스처 | 무겁고 금방 질린다. 지금의 종이 톤 유지 |
| 포착 순간의 분류 질문 | P2. 분류는 치우기·끌어다 놓기에서 |
| 스트릭·점수 게임화 | 쌓인 종이의 '두께'로 충분. 끊기면 죄책감만 남는다 |

## 6. 제스처 지도 (충돌 검토)

| 위치·동작 | 기능 | 충돌·대응 |
|---|---|---|
| 화면 가장자리 0–32dp 안쪽으로 밀기 | 시스템 뒤로가기(삼성) | 앱은 이 띠를 쓰지 않는다(현행) |
| 오른쪽 32–96dp 세로 훑기 | 공책꽂이 스크럽 | 현행. 카드는 이 띠에 놓이지 않게 배치 영역에서 제외 |
| 왼쪽 서류철 탭 | 공책 펼치기 | 현행. 카드를 서류철로 끌어 놓기와 공존(끌기는 길게 누른 뒤) |
| 책상 빈 곳 위로 밀기 | 서랍(앱) | 현행. 카드 위에서 시작하면 카드 끌기로 소비 |
| 책상 빈 곳 두 번 탭 | 포스트잇 | 신규. 한 번 탭은 아무것도 안 함(오작동 방지) |
| 카드 길게 눌러 끌기 | 옮기기·쌓기·공책으로·휴지통으로 | 신규 |
| 팝업 빈 곳 왼→오른쪽 밀기 | 창 닫기 | 현행. **공책 쪽 넘기기와 충돌** → 공책은 첫 쪽(표지)에서 오른쪽으로 넘기면 덮이며 꽂힌다. 그 외 쪽에서는 넘김이 우선 |
| 치우기 모드 위·왼·아래 밀기 | 넘기기·보관·버리기 | 치우기 모드 안에서만 활성 |

## 7. 데이터 모델 영향 (초안)

- 1단계(꺼내 두기·포스트잇·치우기)는 **표 2개 추가**로 가능 — 기존 도구 표는 그대로.
  - `desk_item`: id, kind(STICKY / TODO / MEMO / DOCUMENT / DOODLE / EVENT), refId(원본 id, STICKY는 null), col, row(격자 좌표), tilt, pileId, z, placedAt, carriedCount(이월 횟수), sweptAt
  - `sticky_note`: id, text, inkPath(손글씨 획 파일, 선택), color, createdAt, updatedAt
  - 휴지통 = `sweptAt` + 상태값, 7일 지나면 정리 작업이 삭제(원본 데이터는 원본 도구 규칙을 따름).
- 2단계(오늘 페이지)는 **뷰**: 기존 DAO(Todo·CalendarEvent·Memo)를 날짜로 읽어 합친다. `core:database` 읽기 전용 사용 → 모듈 규칙(feature 간 의존 금지) 준수.
- 3단계(공책 객체·쪽·책장)는 `notebook`, `page` 표와 기존 표에 `notebookId`·`pageNo` 추가 — 마이그레이션 필요, 가장 큰 변경.

## 10. 결정이 필요한 것

1. **첫 화면의 중심**: (a) 지금처럼 도구(공책꽂이) 중심 + 책상 카드 추가 / (b) '오늘 페이지'가 늘 펼쳐진 공책 중심 — 권장: (a)로 시작해 B단계에서 (b)를 기본 카드로.
2. **카드 배치**: 느슨한 격자(권장) vs 완전 자유 배치.
3. **책상 치우기 시각**: 정해진 시각에 벽 쪽지(권장) vs 버튼으로만.
4. **손글씨 비중**: 포스트잇에서 손가락 필기를 기본 제공할지(선택 기능 권장).
5. **용어**: '서류철/도구' → '공책'으로 화면 문구를 바꿀지.
